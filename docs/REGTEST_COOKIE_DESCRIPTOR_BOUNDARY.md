# REGTEST-COOKIE-001 — Descriptor-bound RPC cookie validation (no Core launch)

This increment addresses the separate **RPC cookie pathname race** described in issue #36. Prior `_read_cookie` checked the pathname with `lstat()` and then reopened the *same pathname* with `Path.read_bytes()`. An attacker with write access to the test datadir could replace the file between those operations, potentially changing which RPC credentials were consumed.

`_read_cookie` now uses one `os.open` + `fdopen` descriptor (POSIX `O_NOFOLLOW` where available), with conservative `lstat` → `fstat` before/after bounded read → `lstat` cross-check. It validates file device/inode, size (1..1024 bytes), ctime, mtime, link count 1, regular file type, Windows reparse metadata, and private POSIX mode `0600` (or stricter). Any detected replacement, mutation or malformed cookie is rejected with a **fixed redacted status**. Only one terminal LF or CRLF is tolerated for cross-platform compatibility; embedded control characters and invalid credential shape remain forbidden. The credential still remains solely in `ExplicitRpcAuth(repr=False)`.

New regression suite exercises real temporary-file operations, pre-open pathname replacement, post-read pathname replacement, same-size in-place mutation, symlinks/hardlinks, Windows reparse metadata, malformed/bounded data and no WAM Core process launch. Windows/macOS are validated in native CI, and no test fixture contains a production credential.

**Security limitations:** This closes the straightforward *two pathname opens* race and detects observed inode/size/time drift. It does **not** prove the whole datadir is owned by the runner, protect against an attacker controlling parent directories, guarantee atomic security on every filesystem/platform, or establish the executable-image identity of WAM Core. For Windows, `O_NOFOLLOW` is not generally available and reparse/path replacement is conservatively screened using metadata; kernel-level Windows handle policy needs separate review. No extra launch authority is granted.

The unconditional `CORE_EXECUTION_REVIEW_REQUIRED` remains unchanged. Signed archive review (#81/#83), real readelf finding (#85/#86), PR #84 HOLD, and genuine two-node Core regtest #9 remain separate. No mainnet/testnet, wallet keys, funds, WSP freeze, or upstream WAM Core edits. The next real-node integration step should separately qualify isolated private datadir ownership/ACLs and OS-specific launch binding with DEV WAM.
